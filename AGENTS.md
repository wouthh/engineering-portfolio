# Repository guidance

This repository presents sanitized engineering case studies for `wouthh`.

- Keep the writing concise, technical, and useful to recruiters, engineering managers, and senior engineers.
- Never publish employers, clients, private repository URLs, operational data, personal data, credentials, private paths, or exact professional chronology.
- Use original prose, original diagrams, and clearly labelled synthetic examples. Do not copy private source code.
- Distinguish verified facts, design rationale, generalized lessons, and limitations.
- Do not add unsupported scale, performance, profitability, availability, or business-impact metrics.
- Keep private-project names out of repository metadata, navigation, and social previews. A permitted name may appear once in a deeper case study when technically useful.
- Diagrams must remain understandable without color and need an accessible text equivalent.
- Prefer GitHub-native Markdown. Do not add animated banners, visitor counters, dynamic statistics, icon walls, or decorative badge collections.
- Treat `README.md`, `capabilities.md`, case-study links, and status labels as one documentation contract.
- Validate links, Markdown structure, privacy terms, and the complete diff before publishing.
