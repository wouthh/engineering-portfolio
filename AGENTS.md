# Repository guidance

This repository presents engineering case studies for `wouthh`.

- Keep the writing concise, technical, and useful to recruiters, engineering managers, and senior engineers.
- Never publish employers, clients, private repository URLs, operational data, personal data, credentials, private paths, or exact professional chronology.
- Use original prose and original diagrams. Every diagram needs a text equivalent and must remain understandable without color. Do not copy private source code.
- Do not invent scale, performance, profitability, availability, or business-impact metrics.
- Keep private-project names out of repository metadata, navigation, and social previews.
- Prefer GitHub-native Markdown. Do not add animated banners, visitor counters, dynamic statistics, icon walls, or decorative badge collections.
- Treat `README.md`, `capabilities.md`, and case-study links as one documentation contract.
- Before publishing, validate links, Markdown structure, privacy terms, and the complete diff.

## Writing policy

- Write in first person about my own work. I designed and built my public projects; state that plainly.
- Do not invent metrics. Leave numbers out rather than qualify them.
- Describe professional work as responsibilities and technical decisions, without employer, client, or chronology.
- The README's "About this portfolio" note covers anonymization. Do not repeat evidence disclaimers on individual pages.
- Do not present generic textbook guidance as a case study. A case study describes decisions I made.
- Lead the README with the professional backend case study.
- The profile's project selection and pin order live only in the profile repository's guidance ([`wouthh/wouthh` AGENTS.md](https://github.com/wouthh/wouthh/blob/main/AGENTS.md)). Keep this README focused on its own case studies and notes.
